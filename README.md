# ZAWAZAWA Moderation Review

ZAWAZAWA掲示板の管理人に向けた、通報処理お助けツールです。Codexデスクトップ向けのローカルプラグインで、未処理通報を調査し、Wikiごとの運用基準に沿った対処案を作成・実行します。

開発者は原神wiki2代目管理人です。引退の間際に試作したもので、今後の保守・更新予定はございません。また、ZAWAZAWA・Wikiwiki公式に何らの許諾も得ていません。自己責任において自由に改変・使用してください。日々の通報対応の負担が少しでも減りますよう。

## 何ができるの？

1. Codexで`$zawazawa-moderation`を使うと、未処理の通報を取得できます。通報されたコメントについて、同じツリーのコメントと過去の投稿履歴を一画面で確認できます。初回は先に`$zawazawa-setup`で初期設定してください。
2. 取得した通報に対し、AIが対処案（削除、削除＋規制、何もしない）を作成します。対処案を修正するか、そのまま承認すれば実行までAIが担ってくれます。
3. 対処案は「運用基準」という単一の文書に基づいて作られます。この文書は原神wikiの慣行が元になっていますが、自由にカスタマイズ可能です。
4. 初期提案と最終判断が異なる案件では、基準を変える必要があるか点検します。必要な変更案は別のサブエージェントによるブラインド再判定で検証し、独立検証ができない場合は保留します。基準への反映には別途明示的な承認が必要です。
5. 対象設定で`autonomous`を明示した場合は、承認画面を出さずにエージェントが全案件を判断・実行します。初期値は`restricted`です。スケジュール実行ではブラウザー操作が必要な措置が未実行になる場合があるため、結果報告を確認してください。

## 注意点・限界

1. いわゆるVibe Coding Shitです。開発者はコードを1行も書いていません。SKILL.mdやreferencesはかなり手を入れましたが、設計上の良し悪しはわかっていません。とりあえず動くからヨシ！として公開に踏み切っています。
2. 基準を自己修正する機能はあまり試せていません。この機能がきちんと動き始めた時には、もう運用基準がまとまりきっていたので。

## 対応環境

- macOSまたはWindowsのPC
- Codexデスクトップのローカルプロジェクト
- 初回セットアップ時に必要なソフトウェア取得を承認できること。Node.jsを個別に導入したりPATHを変更したりする必要はありません
- 対象ZAWAZAWAグループの管理権限

Codex CLIとClaude Codeは必要ありません。ZIPから導入する場合はGitを別途インストールする必要もありません。PCを持たない場合、Web・モバイルだけの場合、Linuxは対応していません。

## Codexデスクトップへインストール

次の操作をCodexデスクトップの画面で行います。

1. サイドバーの「プラグイン」を開きます。
2. 「追加」または「ページの操作」メニューから「マーケットプレイスを追加」を選びます（英語表示では`Add`、`Add a marketplace`）。
3. 「プラグインマーケットプレイスを追加」ダイアログに、次のとおり入力します。

    ```text
    ソース (Source): linalena-gw/Zawazawa-Moderation
    Git ref: main
    Sparse paths: 空欄
    ```

4. ダイアログの「マーケットプレイスを追加」を押します（英語表示では`Add marketplace`）。
5. プラグイン一覧でマーケットプレイス「ZAWAZAWA Moderation」を開き、`zawazawa-moderation-review`の詳細画面で「インストール」または「＋」を押します（英語表示では`Install`または`+`）。インストール後、プラグインが有効になっていることを確認してください。

この画面手順は現在のCodexデスクトップ実装をもとにしています。Windows版の配置は未確認で、アプリのバージョンにより表示名や位置が変わることがあります。項目が見つからない場合はCodexデスクトップを更新してから、プラグイン画面を開き直してください。マーケットプレイスの仕組みは[OpenAIのプラグイン開発ドキュメント](https://developers.openai.com/plugins/build/plugins)、ディレクトリについては[プラグインの公式案内](https://learn.chatgpt.com/docs/plugins)を参照できます。

GitHubのソースを追加できない場合は、GitHubの[Code → Download ZIP](https://github.com/linalena-gw/Zawazawa-Moderation)からZIPをダウンロードして展開し、もう一度同じダイアログを開いて、ソース欄に展開先フォルダの絶対パスを入力します。ローカルフォルダをソースにする場合は`Git ref`と`Sparse paths`を空欄にします。たとえば`C:\Users\<ユーザー名>\Documents\Zawazawa-Moderation-main`です。インストール後も、この展開先フォルダは移動・削除せず、そのままにしてください。Codexがそのフォルダへのアクセスを拒否する場合、Windows上のアクセス権や展開先を確認してください。画面操作だけでアクセス拒否が解消するとは限りません。

## 初回設定

プラグインを有効にしたら、実運用専用の空フォルダをローカルディスクに作り、Codexでローカルプロジェクトとして開きます。公開リポジトリのチェックアウト、Git管理下のフォルダ、Codexのキャッシュ、OneDrive同期フォルダは使わないでください。セットアップで保存先を尋ねられたら、いま開いている専用フォルダを指定します。設定や運用基準、結果報告はこの専用フォルダに置きます。

専用フォルダを開いた新しいチャットで`$zawazawa-setup`を呼び、案内に沿って設定してください。必要なネットワーク取得を承認した後、セットアップがNode.js 24.21.0、npm、プラグインの依存関係、共用Chromiumをユーザー領域へ用意し、Codexのユーザー設定へMCPサーバーを登録します。Node.jsやChromiumの手動導入、PATH変更、設定ファイルの手編集は不要です。初回登録または更新時に登録内容が変わった場合は、Codexを再起動して同じチャットを再開するとツールを読み込みます。運用基準テンプレートは対象Wikiに合わせて確認・編集し、専用ブラウザでは管理者本人がログインします。設定と読み取り専用接続の確認が完了するまで、通報の対処は始めないでください。

通常のMCPサーバー起動ではソフトウェアをネットワークから取得しません。ピン留めしたNode.js、コードと依存関係、共用Chromiumはユーザー領域の専用ホームに保存されるため、プラグインキャッシュが作り直されても準備済みデータを再利用します。詳細な準備・再開手順は[初回設定手順](./plugins/zawazawa-moderation-review/skills/zawazawa-setup/references/setup-flow.md)を参照してください。

同梱の統一テンプレートは[ZAWAZAWA利用規約 第6条](https://z.wikiwiki.jp/s/agreement)と[WIKIWIKI 本サービスに関する利用のルール](https://wikiwiki.jp/pp/rules)を基礎に、著者の原神Wiki由来の慣行を加えた初期案です。対象Wikiに合わせて全文を確認・編集してください。詳しい設定手順は[初回設定手順](./plugins/zawazawa-moderation-review/skills/zawazawa-setup/references/setup-flow.md)を参照してください。

## 通常の使い方

初回設定後は、生成された運用フォルダを開いたローカルプロジェクトで`$zawazawa-moderation`を使うか、「未処理のZAWAZAWA通報を調べて」と依頼してください。

初期モードは`restricted`です。skillが読み取り専用で通報と文脈を調べて一覧を作り、管理者が案件ごとの判断を確認して送信します。送信後に元の会話へ戻り、「送信済み」と伝えて一覧のバッチを実行し、結果報告で成功・保留・結果不明を確認します。

全案件をエージェントが判断・実行する`autonomous`は、対象設定で明示的に選んだ場合だけ使えます。権限の意味と変更手順は[プラグインの運用モード説明](./plugins/zawazawa-moderation-review/README.md#対象グループの設定)を確認してください。

## プラグインの更新

プラグイン画面でマーケットプレイス「ZAWAZAWA Moderation」を選び、ページの操作メニューに更新または再読み込みの項目があれば実行します。その項目がない場合はマーケットプレイスを削除し、上の手順で再追加してください。次にプラグインの詳細画面を開き、旧版をいったんアンインストールしてから再インストールし、バージョン`0.4.0`を確認します。

更新後は、運用フォルダを開いた同じチャットで`$zawazawa-setup`を実行し、更新コードに対応したランタイムとブラウザーを確認します。同じコードの準備が済んでいれば依存関係を再インストールしません。新しいコード用ランタイムが必要な場合だけセットアップが準備し、CodexのMCP登録が変わった場合は再起動後に同じチャットを再開します。

## 困ったとき

- マーケットプレイスや「追加」項目が見つからない場合は、Codexデスクトップを更新してプラグイン画面を開き直します。GitHubソースが使えない場合は上のZIP手順を試します。
- プラグインを追加したのにskillが見つからない場合は、有効状態を確認してCodexを再起動し、同じチャットで`$zawazawa-setup`を呼んで初期設定を再開します。ホストが同じチャットを再開できない場合だけ、新しいチャットを使います。
- MCPツールが見つからない、または依存関係エラーが出る場合は、同じチャットで`$zawazawa-setup`を再開してください。専用ランタイムとCodexの登録状態の確認・修復方法は[初回設定手順](./plugins/zawazawa-moderation-review/skills/zawazawa-setup/references/setup-flow.md)を参照してください。セットアップはMCP登録の競合を検出すると既存設定を上書きせず停止します。
- 認証が切れた場合は、専用ブラウザで管理者本人の再認証を行ってから調査を再開します。

## 安全とプライバシー

- 認証は専用ブラウザプロファイルにだけ保存し、普段使いのブラウザからCookieを取得しません。
- ピン留めしたNode.js、コードと依存関係、共用Chromiumはユーザー領域の専用ホームに保存し、Codexのユーザー設定にはMCP起動情報を登録します。運用設定、認証情報、通報データ、結果報告は`node/`、`browsers/`、`runtimes/`やMCP登録へ保存しません。
- 通報者を識別する表示、接続元情報、認証情報は保存・表示しません。
- 一覧での判断、実行許可、実際の送信、成功確認を分離します。
- 結果報告には投稿本文と通報理由が含まれるため、Git管理・共有しません。
