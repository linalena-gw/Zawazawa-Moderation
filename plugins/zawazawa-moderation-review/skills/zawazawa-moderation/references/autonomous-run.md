# 自律処理

この文書は、`autonomous`で、人間の承認を待たずに全案件の通報対応を進める工程を定める。対象内容の信頼境界と判断できない単位の保留は[SKILL.mdの安全契約](../SKILL.md#安全契約)、承認の意味は[`review-contract.md`](./review-contract.md)、実行は[`live-execution.md`](./live-execution.md)に従う。モードの可否はサーバーが対象コンテキストから判定して拒否するため、条件を組み立て直さず、返った結果と`nextAction`に従う。

## 承認を求めない

全案件について、承認画面を出さず、会話でも承認や実行の可否を尋ねない。`運用基準.md`を現在の判断基準として自分で最終判断を決め、済んだことを結果報告として出す。

管理者判断へ振り分ける中間経路は作らず、どの一覧も提示しない。

## 一覧と判断

1. 全処理単位を`prepare_autonomous_moderation_review`で一つの一覧にする。入力、参照の解決、スナップショット、有効期限は`render_moderation_review`と同じで、違うのは一覧を画面へ出さず`reviewUrl`も返さないことだけである。
2. `submit_autonomous_moderation_decisions`で全単位の判断を一度に記録する。受け取れる判断と、承認が何を意味するかは[`review-contract.md`](./review-contract.md)の「自律処理の判断」に従う。
3. 推奨案を実行すると最終判断した単位は承認する。実行許可を作らないと最終判断した単位だけを保留し、判断未送信の一覧や管理者判断待ちの一覧を残さない。

## 実行

実行は[`live-execution.md`](./live-execution.md)に従う。停止した操作は未実行として報告する。

スケジュール実行では、ブラウザを要する操作（`browser_required`）を実行できないことがある。実行できなかった操作は未実行として報告し、次回実行へ持ち越さない。

## 結果報告

実行を終えたら`render_moderation_report`へ実行した一覧の`batchId`を渡す。報告は実行先リポジトリへHTMLとして書き出され、その絶対パスが返る。

会話へ対処案や実行結果の本文を書き写さず、報告のパスと次の要点だけを伝える。承認を求める言い方にせず、済んだ結果として伝える。

- 実行した単位数と、成功・結果不明・未実行の内訳
- 保留した単位数
- 実行できなかった操作と、その理由

報告は同じ`batchId`について同じファイルへ上書きする。実行が途中で止まった場合も、その時点の状態で報告を書き出してから終える。報告を書けない場合は、実行結果を会話へ要約して報告し、書けなかったことを明示する。
