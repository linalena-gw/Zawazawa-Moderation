# 通報への対処メッセージ

この文書は、通報を閉じる操作に付ける利用者向け本文の書き方を定める。処置の判断は実行先の`運用基準.md`に従う。以下は通常本文と、対象が先に削除済みだった場合の代替本文の両方に適用する。

## 書く内容

短いお礼に続けて、通報された投稿の扱いと、必要な場合だけ投稿規制の有無を伝える。

| 判断した内容 | 利用者へ伝える表現 |
| --- | --- |
| 通報された投稿を削除する | 「対象の投稿を削除しました。」 |
| 関連投稿も削除する | 「対象の投稿を関連投稿とあわせて削除しました。」削除件数や投稿番号の列挙はしない。 |
| 投稿者をブロックまたは自動無視にする | どちらも「投稿規制を行いました。」に統一する。種類、識別方法、内部の設定を明かさない。 |
| 削除・規制をしない | 投稿の内容に即した具体的な理由を一文で示す。例：「対象の投稿は復刻時期についての予想・意見のため、削除しませんでした。」 |
| 対象が先に削除済み | 「対象の投稿はすでに削除されていました。」自分が削除したとは書かない。 |

処置前に作る本文は承認候補であり、完了を表す文章があっても実行済みの証拠にはならない。送信内容は確定した操作と対応させ、結果不明や未実行の処置を行ったと報告しない。

## 書かない内容

- 「運用基準」「リポジトリ」「skill」、文書名、条項番号、基準レビューなどの内部用語・手順。
- ブロックと自動無視の区別、通報を内部で完了・無視のどちらとして閉じたか、関連投稿の削除件数。
- 管理者向けの長い根拠、投稿履歴の引用、通報者を識別する情報。

「基準上の削除対象に該当しない」だけでは理由にならない。「何についての、どのような投稿なのか」を述べる。管理者向けの適用条項や根拠は一覧の`basis`へ置き、送信本文へコピーしない。

## 提示前の確認

1. 本文中に内部用語、規制の種類、関連投稿の件数がないか。
2. 削除・規制の記述が、同じ処理単位で選んだ操作と一致しているか。
3. 処置しない場合、本文の特徴を述べた具体的で短い理由になっているか。
4. 先に削除済みの場合の本文が、自分で削除したと誤って伝えていないか。

実行先文書が異なる開示方針を明示している場合は、その指示を優先する。単に内部用語が判断根拠に登場するだけでは、本文への使用許可と解釈しない。
