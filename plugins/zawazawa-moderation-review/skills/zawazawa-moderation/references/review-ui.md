# 一覧提示と判断回収

この文書は、`restricted`で調査済みの全対処案を管理者判断のために一覧UIへ提示し、判断を回収する手順を定める。表示内容の信頼境界は[SKILL.mdの安全契約](../SKILL.md#安全契約)、承認と実行許可の意味は[`review-contract.md`](./review-contract.md)を正本とする。

## 一覧を表示する

1. 調査と判断を完了してから`render_moderation_review`を一回呼び、全処理単位と`targetContextId`を同じ一覧へ渡す。
2. `comments`と`history`へは参照だけを渡す。処置対象はすべて`comments`の参照に含める。
3. サーバーが参照から本文、現在状態、URL、処置対象に付いた全未処理通報を解決できない単位は提示しない。コネクタが使えない場合も本文や通報を手渡しせず、読み取り不能として止める。
4. モデル可視応答は`batchId`、`snapshotToken`、`expiresAt`、件数、利用できる場合の`reviewUrl`だけの要約として扱う。本文の不在を欠落と解釈しない。
5. 一覧を出した後の会話は、一覧の開き方と、送信したら何を伝えるかだけにする。処理単位の内訳、対象コメント、推奨する操作、送信メッセージは画面が示すので会話へ書き写さない。
6. ユーザーには、送信後に画面へ出る案内のとおりに伝えるか、「送信済み」とだけ伝えればよいと案内する。どちらも同じ実行指示として扱う。エージェントが自分で送信しない。

一覧UIだけが、app-onlyのスナップショット取得、代替案プレビュー、判断送信ツールを呼ぶ。エージェントはこれらを直接呼ばず、表示後は`get_moderation_review`で送信状態を取得する。

単位ごとの選択は送信前の編集状態であり、最後の送信操作が判断を確定する。この送信は判断を記録するだけで、ZAWAZAWAの状態を変更しない。

## 送信後を処理する

ユーザーが判断の送信を伝えた時は、その発話が持つ実行指示の範囲を[`live-execution.md`](./live-execution.md)に従って扱う。ホストの会話送信APIは新しいユーザー入力として別の確認を発生させるため、一覧UIから自動送信しない。

その時点で、提示した一覧の`batchId`で`get_moderation_review`を呼ぶ。状態確認だけなら`summary`、実行へ進む場合は`execution`を使う。以降の実行依頼の範囲は[`live-execution.md`](./live-execution.md)、実行許可の有効性は[`review-contract.md`](./review-contract.md)に従う。

## 表示経路

`ui://`を表示できるホストでは埋め込み一覧を使う。表示できない場合は、`render_moderation_review`が`reviewUrl`を返したときだけ同じ一覧をループバックブラウザで開く。

- 管理者が判断の送信を伝えた時点で`get_moderation_review`を呼ぶ。
- `ui://`を表示できず、`reviewUrl`も無い場合は`reviewUrlError`を伝えて止める。
- UIが保存済み完全スナップショットを取得し、`snapshotToken`を照合できない場合は承認を進めない。

`window.openai`の一時状態には一覧同一性と構造選択だけを保存する。補足理由、編集後の送信本文、表示本文、`resolvedPlan`、`resolvedPlanToken`は保存せず、復元後の代替案は再プレビューする。
