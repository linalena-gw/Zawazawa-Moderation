# 既存設定の修復と再認証

この文書は、`$zawazawa-setup`を完了した既存のWiki運用フォルダで、設定の一部が壊れた場合または認証が切れた場合だけ使う。新しいフォルダの作成、依存関係の初回導入、運用基準テンプレートの確認は`$zawazawa-setup`の責務である。

## 新規セットアップとの境界

- `zawazawa.config.json`または`運用基準.md`が無い場合は、調査を始めず「`$zawazawa-setup`でZAWAZAWA通報対応を初期設定して」と依頼する例を示して止める。
- 初回設定では`restricted`だけを生成する。ここで`autonomous`への変更を提案しない。
- 既に得た明示的な回答や承認を尋ね直さない。認証情報、接続元情報、通報者情報を設定やリポジトリへ書かない。

## 既存設定の修復

`get_moderation_target_config`が`target_config_invalid`を返した場合は、返った文言が指す箇所だけを修正する。修正差分を示し、未承認の変更だけ承認を得てから反映する。他のキーを追加せず、運用モードを広げない。反映後は同じ絶対`configPath`で再度束縛する。

`target_not_configured`の場合は設定ファイルを新規作成せず、`$zawazawa-setup`へ誘導する。

## 再認証

設定を束縛できても管理画面が再認証を求める場合は、プラグインディレクトリで`npm run auth:zawazawa -- <グループキー>`を実行する。グループキーは束縛済み設定から取得し、推測しない。開いた専用ブラウザで管理者本人にログインしてもらい、対象グループのコメント管理画面を確認してから閉じてもらう。普段使うブラウザからCookieを抽出しない。

読み取り中に認証切れが判明した場合の復帰位置は[live-read.md](./live-read.md)に従う。

## 戻り先

同じ設定を束縛できたら[SKILL.md](../SKILL.md)の手順2へ戻る。修復または再認証が完了しない場合は、足りない項目とできない処理を一行ずつ示し、調査を始めずに止める。
