# ZAWAZAWA操作の成功確認

この文書は、ZAWAZAWAで行った操作を何を見て成功と判断するかを定める正本である。ブラウザ経路で操作する場合に読む。MCP送信経路では`execute_zawazawa_moderation_operation`が同じ判定を行うため、エージェントは返った`status`に従う。各操作の効果と、それを確認した根拠は[`operation-effects.md`](./operation-effects.md)を正本とする。

下表はブラウザで画面のUIを操作する経路の成功判定である。対象と操作を確認した同じ操作文脈で「直接の成功証拠」に当たる明確な完了通知を確認できた場合は、それだけで成功とする。追加の再読込や現在状態の読み戻しを必須にしない。通知が無い、曖昧、見失った、または操作開始後に中断して再開した場合だけ、「必要時の読み戻し」で現在状態を確認する。ダイアログが閉じたこと、画面遷移、通信終了、実行ジャーナルの記録だけでは成功としない。

| 操作 | 直接の成功証拠 | 必要時の読み戻し |
| --- | --- | --- |
| 削除 | 対象を確認した削除操作の完了通知。 | 対象コメントの管理画面で削除済み状態を確認する。公開ページの不在は成功証拠にしない。 |
| 復元 | 対象を確認した復元操作の完了通知。 | 対象コメントの管理画面で削除状態が解除されたことを確認する。 |
| 自動無視 | 確認ダイアログ確定後の、自動無視設定が完了したことを示す通知。 | 対象投稿者の現在の自動無視設定を管理画面で確認する。既存コメントの「無視」欄は投稿時点の状態であり、現在の投稿者設定を示さない。 |
| 自動無視の解除 | 確認ダイアログ確定後の、自動無視解除が完了したことを示す通知。 | 対象投稿者の現在の自動無視設定が解除済みであることを管理画面で確認する。既存コメントの「無視」欄は成功証拠にしない。 |
| ブロック | 対象と条件を確認したブロック操作の完了通知。 | ブロック管理画面で、承認した対象に対応する制限が有効であることを確認する。 |
| ブロックの解除 | 対象と条件を確認した解除操作の完了通知。 | ブロック管理画面の確認可能な範囲を読み切り、承認した対象に対応する制限が存在しないことを確認する。 |
| 通報の完了 | 対象通報と任意のメッセージを確認して確定した後の、完了処理が成功したことを示す通知。 | 対象`reportId`が処理済みであることを確認し、メッセージを承認した場合は表示された全文との一致も確認する。両方を一つの操作結果として扱う。 |
| 通報の無視 | 対象通報を確認して確定した後の、無視処理が成功したことを示す通知。 | 対象`reportId`がメッセージなしで処理済みであることを確認する。 |
| 公開警告・案内 | 対象と本文を確認した投稿操作の完了通知。 | 対象トピックで、承認した本文と一致する新規投稿を確認する。これは公開警告・案内そのものの成否確認であり、削除等の公開反映確認を兼ねない。 |

削除等が公開ページへ反映されたかの確認は既定の成功判定に含めない。個別の理由がある場合だけ`check_zawazawa_public_visibility`を使い、「公開反映の確認」として管理画面の成功確認と分けて報告する。公開側の不在や非表示を削除成功の根拠にしない。

## 削除の確認の所在

コメント管理画面の「この投稿を削除する」は`data-method="post"`のリンクで、押すとクライアント側の確認を経て`/m/<グループキー>/comment/<トピック番号>/<コメント番号>/delete`へPOSTされる。このURLはGETに405を返し、確認画面を持たない。確認文「本当によろしいですか」はZAWAZAWA側の二段階処理ではなくブラウザ側の安全弁である（2026-08-24に確認）。

したがって、確認UIは対象の同定を代行しない。確認文だけでは対象コメントを識別できないため、対象は操作直前に一意化したリンク、その`href`、現在の管理画面URLから確認する。ブラウザ経路の操作順序は[`browser-execution.md`](./browser-execution.md)に従う。
