# ZAWAZAWA Setup

初回設定を、設定ファイルの手編集なしで安全に完了させる。詳細な工程は[初回設定手順](references/setup-flow.md)を読み、その順序と停止条件に従う。

利用者に求める操作は、保存先と運用基準の確認、初回のソフトウェア取得への承認、登録変更時のCodex再起動、ZAWAZAWAへの本人ログインに限る。Node.js、npm、Chromiumの手動導入、PATH変更、Codex設定ファイルの手編集を求めない。認証情報を会話、設定、運用フォルダへ書かない。

最初に、実際に読み込まれたこのskillの場所からプラグインルートを求め、OSに合うネイティブbootstrapを使う。`--print-root`と`--print-node`で準備状態を調べる。準備が必要で、ソフトウェア取得が未承認なら、公式Node.js 24.21.0のアーカイブとチェックサム検証、npm依存関係、Playwright Chromiumの取得・起動確認を説明し、承認を得る。同じ作業ですでに承認されている場合は再度尋ねず、一度の`--prepare`でそろえる。同じコード用ランタイム、Node.js、共用Chromiumが準備済みなら再導入しない。通常のMCPサーバー起動ではネットワーク取得をしない。

運用フォルダの生成と読み戻しが完了した後、bootstrapの`--run-script register`でCodexユーザー設定へMCP登録を行う。結果が`registered`ならCodexを再起動し、同じチャットを再開して実際のMCPツールが見えることを確認する。`unchanged`なら再起動は不要。登録名の競合で失敗した場合は既存設定を上書きせず、利用者へ競合を示して止める。利用者から登録削除を頼まれた場合だけ、同じbootstrapの`--run-script unregister`を使い、プラグインを無効化またはアンインストールする前に実行する。

初期設定スクリプトは`--print-node`が返す専用Node.jsの絶対パスで実行する。認証と診断はbootstrapの`--run-script auth <グループキー>`または`--run-script diagnose`を通す。依存関係確認、認証、診断、MCPサーバーは準備済みランタイムと共有ブラウザ領域を使う。リポジトリのソースツリーや運用フォルダを実行時環境の代わりに使わない。

既に作成済みの項目は検査して再利用し、同じ質問を繰り返さない。利用者が編集した`運用基準.md`は上書きせず、その内容を正本として再利用する。その他の生成物に差分がある場合は上書きせず、差分と必要な判断を示して止める。
